# TEST-PLAN — сервіс `parser`

Складено **до** написання тестів (вимога CLAUDE.md §Тестування). Для кожної метрики —
сценарії та граничні значення; для watcher/worker — поведінкові сценарії.

Загальні константи, на які спираються межі:
`DEADBAND = 0.02`, `RESAMPLE_HZ = 10` (`dt = 0.1 с`), вікно осциляцій `2.0 с` (20 семплів),
поріг сигнальних змін `N = 3`, згладжування jerk — ковзне середнє 3 семпли (`mode='valid'`),
вікно очікування реакції `3.0 с`, поріг attitude-події `10°` від 5-секундного baseline.

| 9.7 | Атомарний запис | після `write_result` немає `*.json.tmp`, є `*.json` |

**Реальний контрактний баг, знайдений живим тестуванням через веб-UI** (не unit-тестами
парсера — ті самі собі узгоджено перевіряли СТАРУ форму): до фіксу `worker.analyze()`
рахував гістограму лише для `roll` і повертав пласку форму `{bin_edges, counts}` — веб
(`types.ts: AmplitudeHistogram = Record<Axis, Histogram>`) очікував `{roll: {bins,
counts}, pitch: {...}, yaw: {...}}`. Розлад ніколи не виявлявся, бо жоден тест (ні
парсерний, ні e2e веба) не пропускав РЕАЛЬНИЙ вихід парсера через РЕАЛЬНУ сторінку —
e2e-фікстури веба вручну будували дані за "своєю" (правильною) формою, парсерні тести
звіряли лише "свою" (застарілу) форму. У браузері це падало `TypeError: Cannot read
properties of undefined (reading 'bins')`, і React-острів `AmplitudeHistogram` просто
не рендерився — виглядало як "гістограма не показується", хоча причина не мала
стосунку до SSR/гідратації/`reload`. Урок: контракт між сервісами треба хоч раз
перевірити на реальних, а не синтетичних даних з обох боків одночасно.

## 10.10. `crashed` — детекція аварії (`metrics.detect_crash_heuristic`, `worker.analyze`)

Знайдено живим тестуванням на VM: `STAT.Crash` (вбудований детектор ArduPilot)
активний лише в `AUTO` — на ручних режимах (весь профіль здачі — `MANUAL`/
`FBWA`) не спрацює навіть при реальному падінні. Доповнено власною евристикою:
хвіст логу (`CRASH_TAIL_WINDOW_S`=3с) на низькій висоті (`POS.RelHomeAlt` <=
`CRASH_ALT_THRESHOLD_M`=2м) з екстремальним креном/тангажем (>
`CRASH_ATTITUDE_THRESHOLD_DEG`=60°) — ознака удару, не керованої посадки.
`crashed = STAT.Crash (хоч раз True) OR евристика`.

| # | Сценарій | Очікування |
|---|---|---|
| 10.10.1 | Висока висота в хвості логу, будь-який крен/тангаж | не crashed |
| 10.10.2 | Низька висота, рівний крен/тангаж (керована посадка) | не crashed |
| 10.10.3 | Низька висота + екстремальний крен (одна вісь) | crashed |
| 10.10.4 | Низька висота + екстремальний тангаж (одна вісь) | crashed |
| 10.10.5 | Висота рівно на межі порогу (включно) | crashed, якщо крен/тангаж екстремальний |
| 10.10.6 | Порожній `rel_alt` / `dt<=0` | не crashed (безпечний дефолт) |
| 10.10.7 | Хвостове вікно більше за наявні дані | безпечно (numpy-слайсинг за межі — весь масив) |

Не тестується окремо (тривіальний OR, покрито E2E веб-фікстурою
`flight-crashed`): що `STAT.Crash=True` саме по собі теж дає `crashed=True`
незалежно від евристики.
